# Иван Агошков - лендинг под роль AI-инженера

**Лендинг:** https://goshkow.github.io/vacancy-landing/ · **полное CV:** https://cv.goshkow.com/

Это лендинг-портфолио под вакансию AI-инженера (тестовое задание, часть 1). Он не пересказывает резюме, а показывает опыт в работе. Вместо скриншотов на странице живые фрагменты моих продуктов: можно запустить сценарий агента, задать вопрос ассистенту и посмотреть, как агент для кода правит проект.

## Структура страницы

Страница идёт от общего к частному: кто я → что умею, на живых примерах → чем это подтверждено → почему это подходит роли.

1. **Hero.** Роль, специализация и главные цифры. По прокрутке пустое окно Studio собирает сценарий агента из блоков.
2. **Главное.** Пять карточек с ключевыми результатами.
3. **Докки Studio.** Сценарий «Заявки из Telegram» из 10 блоков: голосовое сообщение, STT, база знаний, AI-шаг, CRM. Можно выбрать одно из трёх входящих сообщений и посмотреть, по какой ветке оно пройдёт. Для каждого шага видны чат и JSON на входе и выходе.
4. **Спросите Докки обо мне.** Как диалог с моим ассистентом: вопрос появляется бабблом, ответ проявляется текстом со ссылками на нужный раздел страницы.
5. **Докки App.** Агент для кода: план, diff, запрос разрешения на запуск тестов, результат.
6. **Результаты и опыт.** Цифры по каждому месту работы и по своим проектам.
7. **Под роль AI-инженера.** Четыре блока по задачам роли, затем стек по группам, как в CV.
8. **Контакты.** Telegram, почта, PDF, GitHub.

## Реализация

Статический сайт: HTML, CSS и модули JavaScript, без сборщика, фреймворков и внешних CDN. Визуальный язык взят у лендинга моего продукта [Докки](https://dokky.goshkow.com/landing/): шрифты Montserrat и Unbounded, стеклянная шапка, экраны в высоту окна, чередование тёмных и светлых блоков.

- `index.html` - разметка и тексты.
- `styles.css` - стили, адаптив (1068 / 860 / 734 px), вариант без JS и без анимации.
- `script.js` - шапка, прокрутка, галерея, счётчики, сцены Studio, Докки и Докки App.
- `demo-data.js` - данные сцен: блоки и связи сценария, вопросы и ответы Докки, шаги Докки App.
- `assets/` - шрифты (SIL OFL), знак, иконки Докки, PDF резюме.
- `tests/` - тесты модели сцен (`node --test`) и проверки страницы (`unittest`): ссылки и файлы, уникальные id, `rel="noopener"`, ARIA-ссылки.

Демо не обращаются к моделям, CRM и Telegram: сценарии заранее описаны в `demo-data.js`. Имена, телефоны и проекты в демо вымышлены, это указано на странице.

## Запуск

```bash
python3 -m http.server 8767 --bind 127.0.0.1
```

Затем откройте http://127.0.0.1:8767/. Нужен HTTP-сервер: через `file://` ES-модули не загружаются.

## Проверки

```bash
npm test
```

```bash
npm run check
```

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Проверено в Chrome на ширине 375 и 1440 px: горизонтальной прокрутки и ошибок в консоли нет. Safari и Firefox не проверялись.
